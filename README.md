# Verkehrswert-Rechner Ratingen

A dependency-free web wizard that guides a user through the data needed to estimate the **Verkehrswert** of a residential property in Ratingen using the **Sachwertverfahren** (ImmoWertV).

- **User interface:** German
- **Documentation:** English
- **Runtime:** static HTML/CSS/JavaScript; no build step, no backend, no external packages

> This tool is for orientation and documentation. It does not replace a certified valuation (Verkehrswertgutachten) or the expert judgement of a Sachverständiger.

---

## 1. Quick start

Open `index.html` in a modern browser. All data is embedded in `data.js`, so `file://` works.

Optional local server:

```bash
python -m http.server 8765
# then open http://127.0.0.1:8765/index.html
```

Use the sidebar steps 1–8. Each step starts with a short German guide explaining what is being asked and a compact text extract from the relevant source. Every input change recalculates the result immediately; the right-hand panel and the sidebar show the current value on every step. The state is saved in the browser's `localStorage` and can be reset with **Zurücksetzen**.

**Zurücksetzen** opens an in-page confirmation dialog (never a browser/window prompt) that states exactly what happens: all entered object data and calculation values are replaced by the fresh defaults and the saved input state is overwritten. The chosen theme and language are separate preferences and are kept.

**Eingaben speichern** downloads a JSON file with all inputs. **Eingaben laden** restores such a file. The sidebar offers four anonymised examples in a dropdown (**Reihenmittelhaus**, **Reihenendhaus**, **Doppelhaushälfte**, **Mehrfamilienhaus** with manual Sachwertfaktor); **Beispiel laden** loads the selected one with its BORIS Jahr, Ortsteil/PLZ, Richtwertzone, Gemarkung and Flur. All examples are fictional and contain no real addresses or case numbers. The icon-only **☾/☀** button switches between light and dark themes and remembers the choice in `localStorage`. The language button next to it cycles **DE → EN → ES → DE** and remembers the choice in `localStorage` (`vw-ratingen-lang`). German valuation terms (e.g. Verkehrswert, Sachwert, Bodenrichtwert, NHK, RND, Wohnungsrecht) are intentionally kept in all three languages; the header has fixed button widths and a clamped tagline so switching languages does not resize it.

The BORIS BRW snapshot is stored in `data/boris-ratingen.js` and loaded with a normal script tag, so `file://` still works. It contains only baureifes Land with residential/mixed uses (`ENTW=B`, `NUTA` in W/WR/WA/WB/WS/M/MD/MDW/MI/MU); agricultural and forest BRWs are excluded because they are not usable for this calculator. In step 2 you enter Gemarkung/Flur/Flurstück (Gemarkung has a datalist of the eight Gemarkungen in the snapshot; Flur/Flurstück stay manual because the snapshot has no parcel data), filter the Ratingen zones by year and then by Ortsteil/PLZ (12–13 options per year), pick the WNUM from the zone list, or click a point in the offline zone overview (representative points coloured by BRW on a bundled OpenStreetMap background; these are not official zone boundaries). Selecting a zone or point immediately sets the **Ortsteil, PLZ** filter, the Richtwertzone and the BRW — there is no separate apply step. The background image (`assets/ratingen-basemap.png`) is generated once by `py scripts\build_map_background.py` and bundled locally, so no live tile request is needed; it is © OpenStreetMap contributors (ODbL) and attributed in the UI. When an Ortsteil/PLZ filter is active, a separate zoomed image from `assets/maps/` is shown instead, generated by `py scripts\build_ortsteil_maps.py` together with the georeferenced manifest `data/boris-maps.js`; the BRW dots are registered to that image's extent. The 2020–2026 BRW history then appears in a small chart and table, with a solid line connecting the actual values and a dashed, lighter continuation for the following year. That continuation is an illustrative linear extrapolation, clearly labelled "Prognose" and not an official Bodenrichtwert. It is `mean(BRW) + slope × (forecast year − mean year)` from a least-squares fit over all available Stichtage of the same WNUM, rounded to whole €/m² and clipped to `0…2× the highest observed BRW`; the visible explanation and the PDF report both state that it is not used in the calculation. The official BORISplus.NRW map link remains available to confirm the zone for the actual Flurstück. The BRW can be overwritten manually at any time in the editable field; overwritten values are highlighted and the history panel then shows a short manual-value note instead of the BORIS series. Gemarkung/Flur/Flurstück are documentation fields because the offline snapshot has no parcel geometry.

The **PDF-Bericht** button generates and downloads a PDF Blob directly; it never calls `window.print()` and never opens a printer dialog. The report is written in the language selected in the UI at the moment it is created (DE/EN/ES). It includes the selected BORIS map image with marker, the Bodenrichtwert trend chart, the age/RND timeline (including the model-limit line), the Sachwertfaktor curve and the Baupreisindex chart, plus a `Schritte im Wizard` section with the guide text and explanation blocks from each step, glossary, method sections, official excerpts, source list and warnings. Dedicated sections list every Ausstattungsstufe with its NHK-2010 weight, level, description and example, and every Modernisierungspunkte category with its points, description and example, followed by the total points, the resulting `Modernisierungsgrad` and the RND result. The chart coordinate system uses `y=0` at the bottom and `y=1` at the top, so rising data rises in the PDF.

## 2. Scope

The calculation engine implements:

- Sachwertverfahren for owner-occupied residential property (EFH, ZFH, DHH, REH, RMH; MFH only with a manual Sachwertfaktor).
- Bodenwert derivation from a Bodenrichtwert with adjustable micro-location correction and Übertiefe coefficient.
- NHK 2010 cost classes, weighted Ausstattungsstufe, Destatis-based Baupreisindex, Baunebenkosten, regional factor and add-ons for components outside the BGF. In the UI, each of the nine Gewerke uses a 1–5 slider in 0.5 steps with a short German explanation and a practical example that changes with the slider; the weighted level is linearly interpolated between the five official NHK cost figures.
- Linear Alterswertminderung using GND and RND.
- RND extension from modernization points (ImmoWertV, Anlage 2). In the UI, each measure uses a 0–max slider and shows a short German explanation plus a practical example for the selected point value.
- Market adaptation using the Sachwertfaktoren from the Ratingen Grundstücksmarktberichte 2025 and 2026, including tabular interpolation and regression fallback. The default report is 2026; the factor can be adjusted by entering a percentage, and adjusted values are marked in the UI.
- Optional unentgeltliches Wohnungsrecht, following the method in the main example. Step 7 is collapsed by default and only enabled by its tickbox.
- Plausibility comparison with a typical purchase price supplied by the user.

It does **not** implement the full Ertragswertverfahren or Vergleichswertverfahren. The second supplied example (MFH Köln, 2014) is used as structural guidance only; its market area and old ImmoWertV/SW-RL version are outside the Ratingen Sachwertfaktor dataset.

## 4. Calculation method

### 4.1 Sequence

1. **Object and Stichtag** – Gemarkung/Flur/Flurstück identify the parcel in TIM; the valuation date drives `Gebäudealter = Stichtag − Baujahr`.
2. **Bodenwert** – `BRW × anrechenbare Fläche`, with optional location adjustment and Übertiefe coefficient.
3. **Herstellungskosten** – interpolate NHK 2010 cost class by weighted Ausstattungsstufe, add corrections and non-BGF components, apply Baupreisindex and Baunebenkosten.
4. **Alterswertminderung** – `AWM-Faktor = RND / GND`.
5. **Bauliche Anlagen** – `indexierte HK × BGF × AWM-Faktor`; add Zeitwert Außenanlagen.
6. **Vorläufiger Sachwert** – building/outdoor value + Bodenwert + special adjustments.
7. **Marktanpassung** – multiply by the object-adjusted Sachwertfaktor.
8. **Plausibility / rights** – optional comparison value and optional Wohnungsrecht (whole section off unless the tickbox is checked).

### 4.2 Standardstufe

Nine Gewerke are weighted:

| Gewerk | Weight |
| --- | ---: |
| Außenwände | 23 % |
| Dach | 15 % |
| Fenster und Außentüren | 11 % |
| Innenwände und -türen | 11 % |
| Deckenkonstruktion und Treppen | 11 % |
| Fußböden | 5 % |
| Sanitäreinrichtungen | 9 % |
| Heizung | 9 % |
| Sonstige technische Ausstattung | 6 % |

The resulting value (1–5, fractional values allowed) is linearly interpolated between the NHK cost levels.

### 4.3 RND

- Baseline: `RND = GND − Gebäudealter`, as required by Anlage 2, II.2 whenever the relative age is below the limit for the selected point count.
- From `0` to `20` Modernisierungspunkte, Anlage 2, Tabelle 3 gives a relative-age limit (`abRelAlter`). The model formula is used only when `Alter ÷ GND >= abRelAlter`:

```text
RND = (a × Alter²) / GND − b × Alter + c × GND
```

The result is limited to the linear RND as a minimum and `1.7 × GND` as a maximum. Parameters `a`, `b`, `c` and `abRelAlter` for every point count are stored in `data.js` (ImmoWertV, Anlage 2). Anlage 2, Tabelle 1 allocates the points per modernization measure; Tabelle 2 maps the total `0–20` points to the `Modernisierungsgrad` (`0–1 nicht modernisiert`, `2–5 kleine Modernisierungen im Rahmen der Instandhaltung`, `6–10 mittlerer Modernisierungsgrad`, `11–17 überwiegend modernisiert`, `18–20 umfassend modernisiert`). The PDF report prints the grade text and the point total.

Modernization points are entered with integer sliders (`0 … max`). Each slider displays the selected value as `x / max Punkte` and updates two lines beneath the category: a short German explanation (`Bedeutung: …`) and a practical example (`Beispiel: …`). The texts are stored per point value in `modernizationElements[].explanations` and `modernizationElements[].examples` in `data.js`; they are orientation aids, not a substitute for the official point tables. The same texts, the NHK-2010 weights per Gewerk, the weighted Ausstattungsstufe and the RND result are repeated in the PDF report so all entered values are traceable.

### 4.4 Sachwertfaktor

For the selected report and building class, `data.js` contains:

- the regression `k = a × x^b` (`x` = vorläufiger Sachwert),
- σ and sample size,
- the published factor table.

The table is used by linear interpolation where a value exists. If the value is outside the published span, the regression is used and a warning is shown; the report explicitly warns against extrapolation.

An object-specific adjustment can be entered as a percentage. For example, changing the table value 1.30 to 1.10 is an adjustment of −15.38 %.

### 4.5 Wohnungsrecht

Following the supplied worked Sachwert example:

1. Reduce RND by the statistical life expectancy.
2. Recalculate the Sachwert with the reduced RND (Bodenwert unchanged).
3. Discount the future Sachwert with a life-dependent discount factor.
4. Apply an uncertainty deduction.
5. Add the capitalized annual savings from the future owner taking over maintenance costs.

Discount factor, uncertainty deduction, annual savings and annuity factor are user inputs because they require expert/mortality-table judgement.

## 8. Assumptions and limitations

- Baupreisindex presets are derived from Destatis GENESIS table 61261-0002 using `index / 70.8` for NHK 2010; any value can be entered manually.
- For the 2026 model, Baunebenkosten are treated as included in NHK (0 %). The example uses 17 %; both are supported.
- Bodenrichtwerte in this app are gebietstypische averages. The actual zone BRW should be taken from BORISplus.NRW for the specific property and entered manually.
- The RND model is an orientation model; it does not replace sachverständige Würdigung.
- No full Ertragswertverfahren, Vergleichswertverfahren, income capitalization, or tax/transaction-cost module is included. The BORIS Immobilien-Preis-Kalkulator is linked for manual comparison; there is no automatic BORIS IPK call or API integration.
- Fiscal or legal rights other than the modelled Wohnungsrecht must be assessed separately.

## 9. Maintenance

When a new Grundstücksmarktbericht is published:

1. Update `marketReports` in `data.js` (BRW, Übertiefe, factor parameters, factor table, model description).
2. Add a new option to the report selects in `index.html` / `app.js` if needed.
3. Update the year-specific model notes (GND, BNK treatment, Regionalfaktor).
4. Re-run the example verification in section 6 to make sure the engine still reproduces the reference values.
